# Инструменты

Семнадцать инструментов общего назначения. Ни одного, специфичного для сайта
или задачи, — из них агент собирает любой сценарий сам.

Схемы генерируются из одного места, `tools/registry.py`: описание инструмента
живёт рядом с его функцией, а JSON-схема для модели, реестр имён и MCP-сервер
берутся оттуда же. Продублировать схему негде.

Описания инструментов написаны **по-английски**, хотя весь остальной код
и промпты русские. Причина прозаическая: описания уходят в каждый запрос
и составляют 1494 токена из ~5000 префикса, а по-русски их объём вырос бы
примерно вдвое.

## Сводка

`?` — необязательный параметр. Колонка «необр.» — флаг `destructive`, по нему
работает security layer.

| Инструмент | Параметры | необр. | Что делает |
|---|---|:--:|---|
| **Навигация** |
| `goto` | `url` | | Открыть абсолютный адрес в текущей вкладке |
| `go_back` | — | | Назад по истории вкладки |
| `list_tabs` | `format?` | | Список вкладок с полными URL |
| `switch_tab` | `index` | | Сделать другую вкладку активной |
| `close_tab` | `index` | ● | Закрыть вкладку; последнюю закрыть нельзя |
| **Взаимодействие** |
| `click` | `ref`, `button?` | ● | Клик по элементу. Он же ставит галочки, выбирает радиокнопки и пункты кастомных выпадашек |
| `type_text` | `ref`, `text`, `clear?`, `submit?` | ● | Ввод в поле, textarea или rich-text редактор |
| `select_option` | `ref`, `value` | | Выбор в нативном `<select>` — и только в нём |
| `press_key` | `key`, `ref?` | ● | Клавиша или сочетание, с опциональным фокусом на элементе |

| `upload_file` | `ref`, `path` | ● | Прикрепить файл к `input[type=file]` в обход системного диалога |
| **Чтение** |
| `read_page` | `question`, `ref?`, `format?` | | Задать вопрос о содержимом; отвечает sub-агент, текст страницы в контекст не попадает |
| `find_in_page` | `query` | | Найти фразу и получить refs |
| `screenshot` | `marked?` | | Посмотреть на страницу картинкой с нарисованными refs |

| `finish` | `summary`, `success?` | | Завершить задачу и отчитаться |

## Правила, общие для всех

**Цель задаётся только через `ref`.** Приёма «передай мне селектор» нет. Это
не удобство, а требование задания: инструмент, принимающий селектор, немедленно
превратится в место, где модель их выдумывает, а разработчик — подсказывает.

`ref` выдаётся снапшотом и привязан к узлу DOM, а не к порядковому номеру,
поэтому переживает частичный ре-рендер. Уехавший за край экрана ref остаётся
рабочим: перед ошибкой у фрейма спрашивается, подключён ли ещё такой узел.

**Ошибка — это результат, а не исключение.** Каждый класс ошибки
(`tools/errors.py`) знает, что сказать модели, чтобы она сделала следующий ход,
а не повторила тот же:

| Класс | Что видит модель |
|---|---|
| `StaleRef` | элемент исчез со страницы, вот свежее состояние |
| `NotVisible` | элемент есть, но вне области видимости |
| `Covered` | **что именно** перекрывает элемент |
| `WrongType` | это не `<select>`, для такого элемента нужен `click` |
| `Timeout` | страница не успокоилась, состояние отдано с флагом `unstable` |
| `Navigation` | произошёл переход, вот новая страница |
| `RateLimit` | провайдер ограничил; роутер сам идёт по цепочке моделей |

**Результат всегда сопровождается свежим состоянием страницы.** Агент никогда
не действует вслепую и никогда не «предполагает», что действие сработало.

**Действия отчитываются о наблюдаемом эффекте, а не о факте вызова.** Прокрутка
сообщает, на сколько пикселей сдвинулась страница (и сдвинулась ли вообще).
Клик по переключателю сообщает, в каком состоянии тот оказался. Клик по кнопке
сообщает её подпись, а не только `ref`: после компакции истории строка
`Клик по e67` не значит ничего.

**Диалоги браузера не закрываются автоматически.** `alert`, `confirm`, `prompt`
перехватываются, их текст уходит в снапшот, решение принимает агент.

## Три инструмента, вокруг которых устроено управление контекстом

### `read_page` — чтение без загрязнения контекста

Не возвращает текст страницы. Принимает **вопрос**, отдаёт **ответ**. Между ними
работает sub-агент на дешёвой модели: он видит полный markdown в своём
одноразовом контексте и отвечает парой строк.

Разница на практике: описание вакансии — 3–10k токенов, которые остались бы
в истории основного агента навсегда; ответ — около 150.

### `remember` — память, переживающая компакцию

История сжимается: старые шаги превращаются в однострочники. Всё, что агент
собрал по дороге и хочет использовать в конце, надо положить в scratchpad —
он прикладывается к промпту целиком на каждом шаге.

### `find_in_page` — три разных ответа вместо одного

Инструмент различает три ситуации, и это важнее, чем кажется:

1. текст найден и виден → refs
2. текст есть в разметке, но скрыт → «раскройте свёрнутый раздел или меню»
3. текста нет вообще → «повторять этот поиск бессмысленно: другой регистр,
   другой язык или второй такой же запрос дадут ровно то же самое»

Пока ответ был один на все три случая, агент восемь шагов подряд перебирал
регистры и языки. Третий ответ закрывает именно этот режим отказа —
[`DECISIONS.md`](DECISIONS.md), ADR-039.
