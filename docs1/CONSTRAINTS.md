# Ограничения задания и как они соблюдены

Задание проверяет **архитектурное мышление**, а не количество фич. Нарушение
любого из трёх запретов обесценивает работу целиком, независимо от того,
насколько хорошо агент работает на видео. Поэтому запреты вынесены в отдельный
документ, а проверка на них автоматизирована.

---

## 1. Что обязано быть

### 1.1 Автоматизация браузера

| Требование | Как закрыто | Где |
|---|---|---|
| Программное управление браузером | Playwright поверх CDP | `src/agent/browser/controller.py` |
| Persistent sessions — пользователь входит вручную, агент продолжает | подключение к Chrome с профилем пользователя, `connect_over_cdp` | `scripts/launch_chrome.ps1` |
| Видимый браузер, не headless | Chrome запускается отдельным окном, агент присоединяется | там же |

### 1.2 Автономный AI-агент

| Требование | Как закрыто |
|---|---|
| Модели Claude или OpenAI | провайдер-адаптер; целевая конфигурация — Claude, прототип на GLM (см. §4) |
| Решения без постоянного участия пользователя | цикл идёт до `finish` или `ask_user` |
| Многошаговые задачи с переходами между страницами | реестр вкладок, компакция истории, scratchpad, реестр совершённых действий |

### 1.3 Управление контекстом

> Нельзя просто отправлять целые веб-страницы в контекст AI.

Шесть механизмов, разбор — [`ARCHITECTURE.md`](ARCHITECTURE.md) §7.
Контрольная метрика: **средний снапшот ≤ 4000 токенов** при сыром HTML
в 1.4M токенов на той же странице.

### 1.4 Продвинутые паттерны — требовался минимум один

Сделаны **все три**:

| # | Паттерн | Где | Статус |
|---|---|---|---|
| 1 | Обработка ошибок и адаптация | `core/recovery.py`, `tools/errors.py` | работает по умолчанию |
| 2 | Sub-agent architecture | `core/subagent.py`, `tools/reading.py` | работает по умолчанию |
| 3 | Security layer | `security/guard.py` | реализован, **по умолчанию выключен** |

Про третий отдельно, чтобы не возникло вопроса при просмотре видео. На записи
агент ничего не переспрашивает — это не отсутствие слоя, а его штатная
конфигурация: в брифинге просили не переспрашивать, поэтому
`CONFIRM_DESTRUCTIVE=false` по умолчанию. Включается флагом
`--confirm-destructive`; тогда перед каждым необратимым действием цикл встаёт
и ждёт ответа. Что слой действительно работает, видно на живом прогоне: агент
получил от пользователя отказ на отправку заявки, не упал и продолжил искать
другой путь, а в отчёте честно написал, что задачу выполнить не смог.
Автотестов на сам классификатор нет — это записано
в [`LIMITATIONS.md`](LIMITATIONS.md).

## 2. Что запрещено

### 2.1 Заготовки действий агента

> Заготовки действий агента (например шаги по удалению спама или оформлению
> заказа). Агент должен уметь решать любую новую задачу, сам определять, что ему
> делать дальше в моменте, а не следовать заданному плану.

**Нарушение:**
```python
async def delete_spam():  # заготовленный сценарий
    await open_folder("Входящие")
    ...


if task_type == "email":  # ветвление по типу задачи
    ...
PLAYBOOKS = {"vacancy": [...]}  # предзаписанный план
```

**Допустимо:** инструменты общего назначения (`click`, `scroll`, `read_page`),
из которых агент собирает любой сценарий сам.

**Граница.** Цикл агента — не заготовка: он не знает, *что* делать, только *как*
чередовать «посмотреть → решить → сделать». Заготовка появляется там, где в коде
зашита предметная область задачи.

### 2.2 Преднаписанные селекторы

> Преднаписанные селекторы (например `a[data-qa='vacancy']`) — вместо этого агент
> должен сам определять, на что нажать и какой у этого элемента селектор.

**Единственное допустимое место** — `browser/js/collect.js`, где перечисляются
generic-конструкции HTML, а не признаки конкретного сайта:

```javascript
document.querySelectorAll('a, button, input, select, textarea, [role], [tabindex]')
```

Разница: это описывает **язык разметки**, а не **чей-то сайт**. Такой обходчик
одинаково работает на любой странице, которую никто из нас не видел.

**Граница — куки-баннеры.** Соблазн держать список селекторов «закрыть баннер»
велик и является нарушением. Решается архитектурно: проверка
`document.elementFromPoint` в центре элемента убирает из снапшота перекрытые
элементы и оставляет перекрывающие. Агент видит модалку так же, как человек,
и сам решает её закрыть.

Здесь стоит признаться, что запрет один раз был нарушен, и поймала это
автопроверка, а не внимательность. Ошибка `Covered` описывает агенту помеху,
и в первой версии описание заодно угадывало, чем эту помеху закрывают: внутри
перекрывающего блока искалась кнопка, чей текст подходит под список
`закр|отмен|понятн|принят|соглас|close|accept|dismiss|×`. Селекторов нет,
названий сайтов нет, работает везде — и всё равно это ровно то, что запрещает
§2.3: захардкоженное знание о том, на кнопку с каким текстом нажимать. Третий
греп имел единственным попаданием эту строку. Список убран: описание
перечисляет интерактивные элементы внутри перекрывающего блока с их
настоящими подписями, выбор делает агент ([`DECISIONS.md`](DECISIONS.md),
ADR-041). Побочный эффект оказался важнее формального: список слов выбирал
первое совпадение и на баннерах согласия систематически жал «Принять» —
то есть соглашался за пользователя.

### 2.3 Подсказки по ссылкам и элементам

> Подсказки для агента по ссылкам и элементам. Например, нельзя хардкодить, что
> страница с вакансиями — это `/vacancies`, или что для добавления в корзину надо
> нажимать на кнопку с текстом «Заказать».

**Нарушение — в любом месте, которое видит модель:** промпты, описания
инструментов, тексты ошибок, конфиги.

**Допустимо** — стратегия общего вида, не привязанная к сайту:

```
«Если нужных элементов не видно — прокрути страницу и посмотри снова»
«Если элемент перекрыт, сначала закрой перекрывающий его элемент»
«Автокомплит: введи текст, дождись обновления, затем выбери вариант из списка»
```

**Граница — few-shot примеры.** Примеры допустимы, но только на **вымышленных**
страницах. Пример с настоящим сайтом — это подсказка.

**Граница — память между сессиями.** Агент, вспомнивший «на прошлой неделе
заказывал отсюда», ограничение не нарушает: этот факт он **добыл сам**.
Нарушением было бы предзаполнить память знаниями о сайтах до первого запуска.

**Граница — `goto` по URL от пользователя.** Если пользователь сам написал адрес
в задаче — это его ввод, а не наша подсказка.

## 3. Запрещённые зависимости

Нельзя брать библиотеки, содержащие агентный цикл или LLM-управляемый `act()` —
это ровно тот предмет, который проверяется:

`browser-use`, `stagehand`, `skyvern`, `lavague`, `agentql`, `helium`, `nanobrowser`.

Инфраструктуру брать можно и нужно: `playwright`, `trafilatura`, HTTP-клиенты,
SDK провайдеров, `fastapi`. Граница проходит по вопросу: **кто принимает решение,
на что нажать.** Если библиотека — нельзя. Если наша модель — можно.

## 4. Одно осознанное расхождение

Требование «использует модели Claude или OpenAI» на этапе прототипирования
не выполняется: разработка шла на бесплатных GLM-flash от z.ai.

**Причина.** Бесплатного API-тарифа нет ни у Anthropic, ни у OpenAI, а Gemini
недоступен из России. Отладка на платном ключе сожгла бы бюджет за пару дней
итераций.

**Как закрывается.** Провайдер-агностичный адаптер: `llm/anthropic.py` написан
и работает, переключение — правка `.env` без единой строчки кода. Живые прогоны
на видео сделаны на `claude-haiku-4-5`. Подробности про провайдеров и про то,
почему часть метрик снята на z.ai, — в README и в [`DECISIONS.md`](DECISIONS.md),
ADR-037.

Это единственное расхождение, и оно осознанное. Запреты §2 не нарушаются нигде.

## 5. Автоматическая проверка

Гоняется перед каждым коммитом. Все три проверки намеренно ограничены `src/`.

**Упоминания конкретных сайтов и их элементов** — должно быть пусто:

```bash
grep -rniE "hh\.ru|yandex|mail\.ru|data-qa|vacancy-serp|Откликнуться|Заказать|/search/vacancy" \
  src/ --include=*.py --include=*.js --include=*.md
```

**Признаки заготовленных сценариев** — должно быть пусто:

```bash
grep -rniE "def (delete_spam|apply_to|order_food)|task_type ==|if .*site ==|PLAYBOOK|KNOWN_SITES" src/
```

**Селекторы вне разрешённого файла** — должно быть пусто:

```bash
grep -rnE "querySelector|\[data-|\.click\(['\"]" src/ --include=*.py \
  | grep -v "browser/js/collect.js"
```

Сейчас все три пусты. Пустыми они были не всегда: первый ловил название сайта
в комментарии к обходчику, третий — угаданную кнопку закрытия баннера (§2.2).
Проверка полезна ровно тем, что находит то, чего сам за собой не замечаешь.

Почему граница именно по `src/`:

| Где | Можно называть сайты | Почему |
|---|---|---|
| `src/` | **нет** | это и есть агент; знание о сайте здесь — заготовка |
| `evals/tasks.yaml` | да | это текст, который вводит пользователь, а не знание агента |
| `docs1/`, `README.md` | да | документация описывает, на чём проверяли |
| `runs/`, `memory/` | да | добыто агентом на прогоне; в git не попадает |

## 6. Чек-лист самопроверки

| Пункт | Статус |
|---|---|
| Агент проходит задачу на сайте, который в коде нигде не упоминается | да |
| Ни один селектор приложения не встречается вне `collect.js` | да, грепом |
| В промптах нет названий сайтов, путей и текстов кнопок | да, грепом |
| Few-shot примеры — на вымышленных страницах | да |
| Ни один запрещённый пакет не в зависимостях | да |
| Целая страница ни при каких условиях не уходит в контекст | да, sub-агент + потолки |
| Средний снапшот ≤ 4000 токенов, замерено и записано | да, кроме почтового SPA (~5.4k) |
| Реализован минимум один продвинутый паттерн | все три |
| Браузер видимый, сессия персистентная | да |
| Переключение на Claude — только правка `.env` | да |
| В репозитории нет секретов | да, `.env*` в `.gitignore`, кроме `.env.example` |
