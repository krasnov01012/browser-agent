# Browser Agent

Автономный AI-агент, который управляет **настоящим видимым Chrome** и выполняет
многошаговые задачи, поставленные обычным текстом.

```
«Открой почту и удали весь спам»
«Найди 3 вакансии логиста и откликнись на них»
```

Агент не знает заранее ни одного сайта. Он смотрит на страницу, решает, что
делать дальше, действует, смотрит на результат — и так до выполнения задачи или
до момента, когда ему действительно нужен человек.

## Ключевые решения

| | |
|---|---|
| **Никаких заготовок** | ни одного селектора, шага или подсказки по сайту. Всё — решения модели в моменте |
| **Настоящий браузер** | подключение к вашему Chrome по CDP: сессии уже залогинены, антибот не срабатывает |
| **Страница ≤ 4k токенов** | гибрид AX-дерева и DOM вместо сырой разметки. Сырой HTML той же страницы — 1.4M токенов |
| **Провайдер сменный** | GLM для прототипа, Claude — правкой одной строки в `.env` |
| **Три продвинутых паттерна** | все три, а не один: обработка ошибок, sub-агент, security layer |

## Как это устроено

```
задача текстом
      │
      ▼
┌─────────────────┐   ┌──────────────┐   ┌─────────────────┐
│   Agent Loop    │──►│ Tool Registry│──►│   Browser       │
│                 │   │  17 tools    │   │   Controller    │──► CDP ──► Chrome
│  ◄─ PageState ──┼───┤              │   │   + Snapshot    │            (видимый,
└────────┬────────┘   └──────────────┘   └─────────────────┘             ваш профиль)
         │
    ┌────┴─────┬──────────────┬─────────────┐
    ▼          ▼              ▼             ▼
 Context   Sub-agent     LLM Router    Memory + Guard
 Manager   (extractor)   основная →    факты между
 + Ledger                запасная      сессиями
```

На каждом шаге модель получает **сжатое состояние страницы**, а не HTML:

```
URL    https://example.test/search?text=AI+инженер
TABS   [0*] example.test — Работа AI  │  [1] mail.example.test
SCROLL 1200 / 8400  (14%)

[e12] textbox  "Профессия, должность"  = "AI инженер"
[e13] button   "Найти"
[e21] link     "AI Engineer — Компания А"  → /vacancy/12345
[e22] button   "Подать заявку"
       × ещё 47 карточек той же структуры
↓ ещё ~120 элементов ниже, прокрутите
```

Подробности — [`docs1/ARCHITECTURE.md`](docs1/ARCHITECTURE.md).

## Три продвинутых паттерна

Задание требовало **минимум один**. Сделаны все три.

### 1. Обработка ошибок и адаптация

Семь классов ошибок инструментов, каждый со своей стратегией восстановления
и своим текстом для модели: `StaleRef` пересобирает снапшот, `Covered`
сообщает, **что именно** перекрывает элемент, `RateLimit` уводит роутер
на следующую модель в цепочке.

Поверх — четыре независимых детектора буксования, потому что лечатся они
по-разному: зацикливание (в окне из десяти шагов, а не подряд), война
с перекрытиями, перебор формулировок и тупик по отпечатку страницы. Все
подсказки **возвращаются, если их проигнорировали**.

Отдельно: смерть браузера — это результат прогона, а не падение. Закрытое окно
завершает задачу штатно, с отчётом и накопленными фактами.

`core/recovery.py`, `tools/errors.py`

### 2. Sub-agent architecture

`read_page` не возвращает текст страницы. Он принимает **вопрос**, а отвечает
на него отдельный агент-экстрактор на дешёвой модели, который видит полный
markdown в своём одноразовом контексте. Основной контекст сырую страницу
не видит никогда: 3–10k токенов превращаются в ~150.

`core/subagent.py`, `tools/reading.py`

### 3. Security layer

Перед необратимым действием дешёвая модель получает имя действия, аргументы
и подпись цели и отвечает, необратимо ли оно. Никаких списков «опасных кнопок»,
классификация семантическая.

**По умолчанию выключен** (`CONFIRM_DESTRUCTIVE=false`) — в брифинге просили
не переспрашивать, и на видео агент поэтому ничего не спрашивает. Включается
флагом `--confirm-destructive`. Что слой работает, видно в логах: в прогоне
`405f52346392` пользователь отказал в отправке заявки, агент не упал, попробовал
другой путь и честно отчитался, что задачу выполнить не смог.

`security/guard.py`

## Метрики

Две таблицы, а не одна, и это принципиально. Ключ, купленный для доступа
к Claude из России, ведёт не на Anthropic: заголовки ответа выдают шлюз
`new-api` поверх Kiro. Он сам считает числа кэша, сам считает `count_tokens`
(ошибаясь в полтора раза), не соблюдает `max_tokens` и подставляет свой
системный промпт перед нашим. Пополнить баланс Anthropic напрямую к сдаче
не вышло — реселлеры на выходные закрылись.

Поэтому контролируемые замеры сняты на **z.ai**, где эндпоинт настоящий,
`usage` честный и кэш живой, а живые сценарии на Claude приведены отдельно
и помечены как непроверяемые. Разбор — [`docs1/DECISIONS.md`](docs1/DECISIONS.md),
ADR-037.

### Контролируемый набор — z.ai GLM, кэш живой

Три безопасные задачи, по два прогона каждая, `python evals/run.py`. Медианы.

| Задача | Прошло | Шагов | Вход | Выход | Кэш | Задержка модели | Снапшот, ср. |
|---|:--:|--:|--:|--:|--:|--:|--:|
| Открыть страницу и пересказать | 2/2 | 3 | 13 841 | 680 | 49% | 83 с | 34 |
| Найти статью и извлечь два факта | 2/2 | 7,5 | 61 808 | 1 005 | 47% | 177 с | 1 926 |
| Заполнить и отправить форму | 1/2 | 15 | 77 128 | 3 814 | 81% | 511 с | 100 |

«Вход» и «Выход» включают вызовы sub-агента чтения, «задержка модели» — только
основной цикл, поэтому вторая колонка не делится на первую.

Кэш здесь настоящий: доля посчитана эндпоинтом, который её действительно
считает. К третьему прогону она доходит до 81% — префикс перестаёт стоить
денег, платится только за прирост истории. Это и есть цифра, ради которой
префикс держится неизменным (ADR-038).

Задержка большая не из-за агента: бесплатный тариф GLM отвечает по 20–35 секунд
на запрос. На `claude-haiku-4-5` те же шаги идут втрое быстрее — видно
по второй таблице.

**Про 1/2.** Упал не сценарий, а самоотчёт. Форма заполнена и отправлена верно
за восемь шагов, но страница результата — голый JSON без слова «принято»,
и подтверждения там нет физически. Агент четыре раза переформулировал вопрос
к странице, детектор буксования это заметил и одёрнул его, после чего агент
посмотрел на страницу картинкой и **честно отчитался о неуспехе, а не выдумал
успех**. Прогон `6844a56cf36d`, шаги 9–14. То же поведение на `read_page`,
которое ADR-039 закрыл для `find_in_page`, — детектор ловит его на четвёртом
повторе, а не на втором.

### Живые сценарии — claude-haiku-4-5 через реселлер

Прогоны с записи. Числа честно сняты с логов, но **их источнику доверять
нельзя**: доля кэша посчитана шлюзом, а не Anthropic.

| Сценарий | Итог | Шагов | Вход | Выход | «Кэш» | Задержка модели | Снапшот, ср. |
|---|:--:|--:|--:|--:|--:|--:|--:|
| 3 отклика на вакансии | успех | 7 | 65 306 | 785 | 47% | 21,5 с | 1 601 |
| 3 отклика, повтор | успех | 8 | 64 899 | 878 | 66% | 25,4 с | 894 |
| Удалить спам (первые 10) | успех | 20 | 320 780 | 2 170 | 37% | 73,0 с | 5 137 |
| Удалить спам (все 78) | успех | 10 | 144 568 | 1 099 | 31% | 32,1 с | 4 290 |

«Задержка модели» — сумма времени ответов LLM, без ожидания браузера; полное
время прогона больше.

Для сравнения — те же два сценария **до** исправлений от ADR-039, в тот же
вечер: задача «три отклика» отправляла четыре заявки, а задача про спам
уходила в перебор формулировок и обрывалась на десятом шаге, ничего не удалив.

### Что видно из профиля расхода

| статья | доля |
|---|---:|
| статический префикс (промпт + схемы инструментов) | 65% |
| история и состояние страницы | 35% |
| вывод модели | 1% |

Отсюда приоритет: главный рычаг — не сжимать снапшот дальше, а держать префикс
в живом кэше. Тот же прогон на эндпоинте с работающим кэшем стоил бы примерно
вдвое дешевле ([`docs1/DECISIONS.md`](docs1/DECISIONS.md), ADR-038).

Средний снапшот укладывается в контрольные 4000 токенов везде, кроме почтового
веб-клиента: одна страница-приложение с сотнями элементов даёт ~5.4k.

## Запуск

### 1. Chrome с портом отладки

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start_browser.ps1
```

Откроется обычное окно Chrome с отдельным профилем. **Залогиньтесь вручную**
в нужные сервисы — профиль сохранится между запусками. Скрипт не завершится,
пока порт отладки не начнёт отвечать: агент, стартовавший раньше браузера,
падает на подключении.

Личный Chrome закрывать не нужно: профиль отдельный, окна живут рядом. А вот
порт отладки задаётся только при старте процесса — добавить его к уже открытому
окну нельзя.

### 2. Агент

```bash
cp .env.example .env      # вписать ключ провайдера
pip install -e .
```

`playwright install` не нужен: агент подключается к вашему Chrome, свои браузеры
ему не требуются.

```bash
python -m agent.main --ui              # веб-панель на :8000
python -m agent.main --cli             # терминальный REPL
python -m agent.main --task "..."      # разовый запуск
```

Флаги: `-v` — показывать ход мысли, `--confirm-destructive` — спрашивать перед
необратимыми действиями, `--no-memory` — не переносить факты между запусками.

На Windows то же самое одной командой — с проверкой венва, `.env` и живого порта
отладки до старта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start_agent.ps1
```

`-Task "..."` — разовый запуск, `-Rehearsal` — репетиция (спрашивает перед
необратимым, память не пишет). Рядом лежат `.cmd`-обёртки для запуска двойным
щелчком.

### Docker

Chrome остаётся на хосте, в контейнере только агент:

```bash
powershell -ExecutionPolicy Bypass -File .\scripts\launch_chrome.ps1
docker compose up --build
```

Порт отладки при этом остаётся на `127.0.0.1` — наружу его открывать не надо:
Docker Desktop проксирует `host.docker.internal` в loopback хоста. Это важно
для безопасности: открытый порт отладки даёт полный контроль над браузером
всякому, кто до него дотянется, — включая доступ к вашей открытой почте.

## Проверка, тесты, замеры

```bash
python scripts/smoke_llm.py     # работает ли ключ, есть ли tool-calling и кэш
python -m pytest                # 125 тестов, без браузера и без сети
python evals/run.py --repeat 3  # набор замеров
```

Тесты проверяют то, что легко сломать рефакторингом и трудно заметить глазом:
отрисовку состояния страницы и пометки изменений, компакцию истории, детекторы
буксования, реестр совершённых действий, привязку аргументов инструментов, выбор
способа извлечения текста. Почти каждый закрывает конкретный дефект, найденный
в прогоне, — ссылка на решение стоит в docstring.

Поведение на живых страницах ими не проверяется: для этого замеры.
Задачи — [`evals/tasks.yaml`](evals/tasks.yaml), результат прогона ложится
в `evals/results.json`. Замер из таблицы выше сохранён целиком:
[`evals/results.zai.json`](evals/results.zai.json) — по каждой попытке видно
`run_id`, шаги, токены и причину, по которой она зачтена или нет.

Замер и браузер делят один Chrome. Пока набор идёт, работать в этом окне нельзя.

## MCP-сервер

Те же инструменты выставляются наружу по MCP — любой MCP-клиент может водить
браузер сам, без нашего цикла:

```bash
pip install -e ".[mcp]"
python -m agent.main --mcp        # транспорт stdio; то же — browser-agent-mcp
```

Смысл не в интеграции ради интеграции. Реестр инструментов задумывался как
единственный источник правды об именах и схемах, и MCP-обёртка — проверка этого
утверждения: схемы берутся из `Tool.spec()`, вызовы идут через
`ToolRegistry.invoke()`, руками не написано ни одной. Проверка пройдена —
дублировать не пришлось ничего.

Заодно выяснилось, сколько работы делал цикл, пока его никто не считал. В MCP
цикла нет, а `click(ref)` без свежего снапшота бесполезен, поэтому сессия сама
решает, когда снимать состояние и кому его отдавать. Разбор и список того,
чего в этом режиме нет, — [`docs1/LIMITATIONS.md`](docs1/LIMITATIONS.md) §5.

Режим экспериментальный: на живом браузере через настоящий MCP-клиент
не проверялся.

## Чем это отличается от готовых решений

Написать такое поверх `browser-use`, `Stagehand` или `Skyvern` — час работы,
и это была бы сдача чужого агентного цикла: ровно того предмета, который
проверяется. Поэтому сюда не взято ничего, что само решает, на что нажать.
`playwright`, `trafilatura`, SDK провайдеров — инфраструктура, её брать можно.
Граница проходит по вопросу «кто принимает решение».

По существу отличий три.

**Никакого `act("нажми кнопку заказа")`.** В Stagehand LLM превращает
формулировку в селектор — то есть селектор всё-таки появляется, просто его
пишет модель. Здесь цель адресуется только `ref` из свежего снимка; принять
селектор инструменту физически неоткуда.

**Страница не уходит в контекст ни в каком виде.** Не «сжатый HTML»,
не «упрощённый DOM» — гибрид AX-дерева и DOM с проверкой видимости через
`elementFromPoint`, около 4k токенов там, где сырой HTML даёт полтора
миллиона. Текст страницы читает sub-агент в одноразовом контексте и отдаёт
основному агенту пару строк.

**Видимый Chrome с профилем пользователя, а не свой браузер.** Никаких
попыток обойти антибот-защиту: пользователь логинится руками, агент
подключается по CDP и продолжает в его сессии.
