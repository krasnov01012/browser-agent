Инструкции для AI-агентов (Claude Code, Codex, Cursor), работающих в этом репозитории.

## 1. Что это

Сайт студии **Krasnoff Development** (RU/EN): заказная разработка ПО, цифровые продукты,
AI и автоматизация, интеграции данных, инфраструктура и сопровождение после запуска.
Аудитория — предприниматели, стартапы, малый и средний бизнес; Россия/СНГ и международный
рынок равнозначны.

Сайт оценивают **с первой секунды**: он сам — портфолио разработчика. Планка — индивидуальная
арт-дирекция и инженерная отделка, а не «AI-шаблон лендинга».

Статусы в документах и разметке:

| Метка | Значение | Как обращаться |
|---|---|---|
| `[APPROVED]` | прямо подтверждено владельцем | не менять без запроса |
| `[PROPOSED]` | идея дизайнера/агента | можно реализовать, **нельзя** выдавать за утверждённое |
| `[VERIFY]` | факт требует сверки с кодом продукта/CI | не публиковать как факт |
| `[RESTRICTED]` | запрещено на публичных страницах | не использовать вообще |
| `[OPEN]` | не решено | вынести в `docs/OPEN_QUESTIONS.md` |

В HTML те же статусы ставятся атрибутом `data-status="draft|proposed|placeholder|verify|reserved"`;
`?review` в адресе подсвечивает их (режим ревью для владельца).

## 3. Жёсткие ограничения (без явного решения владельца не меняются)

- Название — **Krasnoff Development**. Знак ® **не** использовать (регистрация не подтверждена).
- **Никаких публичных цен**: ни «от X», ни ставок, ни пакетов, ни калькулятора, ни обязательного поля «бюджет».
  Вместо цен объясняем, *как* готовится индивидуальное предложение.
- **Одна универсальная форма** заявки; посетитель выбирает канал ответа **Telegram или Email**.
  Project Architect — дополнительный бриф, **не** оценка стоимости. Оба идут в один endpoint.
- Hero — **Balanced Composition**: типографика и 3D-знак K равнозначны (~52/48).
- K — **ясная латинская K**: одна вертикальная опора, две отдельные диагонали, металл, коралловый узел.
  После сборки — **Subtle Interactive** (наклон за курсором ±3–5°, мягкая реакция на скролл),
  без свободного вращения. Есть fallback для reduced-motion / без WebGL / мобильных.
- Ритм **Editorial Contrast**: тёмный Hero → светлые Услуги → тёмные Работы → дальше осмысленно.
- **Seshat и MARK — собственные независимые продукты**, не заказы клиентов. Не выдумывать клиентов,
  команду, отзывы, награды, метрики, сроки ответа, SLA.
- Коммерческие проекты под NDA — **никаких** названий, логотипов, скриншотов, деталей, даже «анонимно».
- Студия подаётся институционально, но **без вымышленных сотрудников**: сейчас её ведёт основатель.
- Иллюстрации на месте будущих демо **всегда** подписаны (`ИЛЛЮСТРАЦИЯ — ДЕМО-ЗАПИСЬ ГОТОВИТСЯ`,
  `СХЕМА · СИНТЕТИКА — НЕ ИНТЕРФЕЙС ПРОДУКТА`). Никаких выдуманных скриншотов Seshat SPA
  или «дашборда» MARK.

## 4. Репозиторий публичный — правила приватности

`krasnov01012/browser-agent` — **публичный** репозиторий. Хэндофф-архив помечен PRIVATE.

- **Не коммитить** исходный архив, `06_INTERNAL`, мастер-бриф целиком, договоры, промо-карточки
  с личным Telegram, приватные настройки/профиль MARK, любые данные из реальных переписок.
- В `docs/brief/` лежат **санитизированные** выжимки: без имён NDA-клиентов, без личных контактов,
  без приватных фильтров MARK. Если нужен исходник — попроси владельца загрузить архив; распаковывай
  его вне репозитория (`handoff/` и `*.zip` в `.gitignore`).
- Публичные контакты (Telegram/email студии, реквизиты) — только явной конфигурацией, когда
  владелец их утвердит. Личный Telegram владельца без его решения не публиковать.
- Секреты — только через переменные окружения сервера, никогда в клиентский бандл (`PUBLIC_*` видны всем).

## 5. Стек

| Задача | Выбор | Почему (подробно — `docs/DECISIONS.md`) |
|---|---|---|
| Фреймворк | **Astro 7**, статическая сборка | ноль JS по умолчанию, острова, честный SEO/hreflang, i18n-маршруты |
| Язык | TypeScript strict | типизированные словари RU/EN — EN обязан повторять форму RU |
| 3D | **Three.js** (ванильный, ленивый импорт) | одна сцена — React/R3F не нужен |
| Скролл | **Lenis** (сглаживание без перехвата) | отключается при `prefers-reduced-motion` |
| Стили | собственный CSS на токенах, scoped-стили Astro | никакого Tailwind-шаблона; токены — `src/styles/tokens.css` |
| Шрифты | Geist Variable + IBM Plex Mono (self-hosted, OFL) | `[PROPOSED]`, кириллица проверена |
| Node | ≥ 22.23.4 (см. `.nvmrc` = 24) | требование Astro 7 |

Новые зависимости — только с записью в `docs/DECISIONS.md`. Анимационные библиотеки (GSAP и т.п.)
не подключены сознательно: всё движение — CSS, scroll-driven animations и небольшие утилиты в `src/scripts/motion.ts`.

## 7. Команды

```bash
npm install
npm run dev            # http://localhost:4321/ru/
npm run build          # статическая сборка в dist/
npm run preview
npm run check          # astro check (типы)
npm run qa:shots       # скриншоты 1440/1280/768/390 + переполнение + ошибки консоли → qa/
QA_REDUCED=1 npm run qa:shots    # то же с prefers-reduced-motion
node scripts/qa-screenshots.mjs /en/work/mark/ 390   # одна страница/ширина
```

Переменные окружения — `.env.example` (`SITE_URL`, `PUBLIC_LEADS_ENDPOINT`).
Без `PUBLIC_LEADS_ENDPOINT` форма **не изображает успех**: показывает, что приём не подключён.

## 8. Конвенции кода

- Комментарии, документация, тексты интерфейса — **на русском**; идентификаторы и ключи — на английском.
- Любой видимый текст — через словари (`src/i18n`, `src/content`), сразу на обоих языках.
  Локализация по смыслу, не пословно; проверяй длинные русские слова на узких колонках.
- Цвета — только токены. Коралловый `#FF6548` — действие/сигнал, не декоративная заливка.
  Для кораллового текста на ivory — `--coral-strong` (контраст AA).
- Крупные заголовки на кириллице: кегль от ширины колонки (`cqi`), маска строки оставляет запас под Ё/Й.
- Движение: только `transform`/`opacity`/`clip-path`; всё декоративное — под `.motion`
  (класс ставится, только если нет `prefers-reduced-motion`); циклы — под `[data-play].is-playing`
  (останавливаются вне экрана). Никакого scroll-jacking и pinning.
- Контент виден без JS (кроме мастера брифа — у него есть короткая форма как запасной путь).
- Доступность: семантические заголовки, видимый фокус, клавиатура везде, Escape закрывает меню,
  `aria-*` у вкладок/аккордеона, ошибки форм связаны через `aria-describedby`.
- Файлы ≤ ~400 строк; дробить раньше.

## 9. Как работать (обязательный цикл)

1. Прочитай `docs/STATUS.md` и `docs/OPEN_QUESTIONS.md` — что сделано и что ждёт решения.
2. Сделай ограниченный шаг (одна секция / одна страница).
3. `npm run build && npm run qa:shots` — **посмотри скриншоты** 1440 и 390 (и 768), проверь
   переполнение = 0 и пустую колонку ошибок. Проверь режим reduced-motion.
4. Сравни с критериями: `docs/brief/02_DESIGN_SYSTEM.md` (рубрика 0–5, анти-паттерны).
5. Обнови `docs/STATUS.md`; новые нерешённые вопросы — в `docs/OPEN_QUESTIONS.md`.
6. Не объявляй готовым то, что проверено только сборкой: нужен реальный рендер.

## 10. Чего не делать

- Не изобретать замену знаку K; не использовать v01; не брать шрифтовую «K» вместо знака.
- Не делать сетки одинаковых карточек с иконками, «светящиеся пятна», глассморфизм, неон,
  счётчики-метрики, длинные лоадеры, автоплей видео в Hero.
- Не публиковать непроверенные цифры (тесты, сроки наблюдений, «время сэкономлено»).
- Не изображать MARK публичным SaaS/автооткликом; Seshat — готовым веб-приложением или с включённой синхронизацией Google Calendar.
- Не строить CRM или калькулятор цены без отдельного запроса.
- Не расширять объём молча: всё, что не обсуждалось с владельцем, — черновик + пункт в `OPEN_QUESTIONS.md`.
